### Methodology Observation: Backtest vs Live Signal Log

Key structural differences identified:

**Backtest (stricter):**
- Requires Oracle + Titan agreement (both must point same direction)
- Soft macro guard: blocks Oracle signals counter to 1D bias
- BTC gate: skips candles where BTC Oracle = SELL/STRONG_SELL
- Blocks SLEEPING + VOLATILE market states

**Live signal log (looser):**
- Titan only — no Oracle requirement
- Regime filter: BULL → LONG only, BEAR → SHORT only (BTC weekly EMA50)
- Blocks SLEEPING + VOLATILE
- No Oracle macro guard

**Why the live watchlist is still profitable:**
1. Curated coins — only coins that pass backtest enter. Bad coins are removed promptly.
2. Regime filter — no counter-trend trades ever fire.
3. SLEEPING/VOLATILE blocks — chop is filtered out.

**Risk to monitor:** Titan-only live signals will be noisier than Oracle+Titan backtest signals. Over time, live WR may drift below backtest WR. The v2 methodology review scheduled for ~2026-06-01 is the right checkpoint to compare these.

**Conclusion:** No changes needed to the current approach. Watchlist quality is the primary lever — keep maintaining it through regular backtest reviews.
