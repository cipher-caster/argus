## P0 — Critical: Trading Logic Correctness

These bugs directly corrupt trade outcome data and backtest validity.

### 1. Tiebreaker logic inverted in paper trading resolution
**File:** `backend/app/trading/orchestrator.py:357–366`

When both TP and SL are within the same candle's range, the orchestrator uses candle direction to break the tie — but the mapping is backwards:

| Position | Candle | Current result | Correct result |
|----------|--------|----------------|----------------|
| LONG | Bullish (close ≥ open) | LOSS | **WIN** (price went up → TP hit first) |
| LONG | Bearish (close < open) | WIN | **LOSS** (price went down → SL hit first) |
| SHORT | Bearish (close ≤ open) | LOSS | **WIN** (price went down → TP hit first) |
| SHORT | Bullish (close > open) | WIN | **LOSS** (price went up → SL hit first) |

**Impact:** Every ambiguous candle reports the wrong outcome. Win rates are artificially distorted in both directions.

### 2. FVG timestamp off-by-one (look-ahead bias)
**File:** `backend/app/indicators/calculator.py:364, 374`

In `_fvg_to_list()`, the timestamp assigned to each Fair Value Gap uses `df['timestamp'].iloc[i-1]` instead of `iloc[i]`. The FVG forms at candle `i` (the candle that closes the gap), but is recorded at candle `i-1`.

```python
# Bug — uses candle before the one that forms the FVG
ts = df['timestamp'].iloc[i-1]
# Should be:
ts = df['timestamp'].iloc[i]
```

**Impact:** FVGs appear on chart one candle too early. In backtesting, this constitutes look-ahead bias — the FVG is "available" before it actually formed, making confluence signals appear stronger than they are in real conditions.

## P1 — High: Incorrect Data Displayed / Debugging Blind Spots

### 3. Cache key mismatch — refresh button never invalidates best-setups
**File:** `frontend/src/components/features/dashboard/DashboardStatusBar.tsx:298`

The refresh handler calls:
```typescript
queryClient.invalidateQueries({ queryKey: ["best-setups"] })
```

But the actual query key (set in `useAnalyticsData.ts`) is:
```typescript
["analytics", "best-setups", timeframe, limit]
```

TanStack Query v5 prefix matching requires the invalidation key to be a prefix of the actual key. `["best-setups"]` does not match `["analytics", "best-setups", ...]`.

**Fix direction:** Change to `queryKey: ["analytics", "best-setups"]` to use correct prefix.

**Impact:** The refresh button appears to work but never actually invalidates the best-setups cache. Users see stale data after clicking refresh.

### 4. SL percentage displayed with wrong sign for short positions
**File:** `frontend/src/components/analytics/BestSetups.tsx:22`

```typescript
slPct = isLong ? pct(item.entry, item.sl) : pct(item.sl, item.entry)
```

For a SHORT with `entry=100` and `sl=110`, this computes `((110-100)/100)*100 = +10%`. It should display as a negative value (a loss magnitude) since SL being above entry for a short represents an adverse move.

**Impact:** Traders reading BestSetups may misinterpret risk magnitude for short positions — a +10% displayed value suggests gain when it should signal a 10% loss.

### 5. Silent exception swallowing — zero logging on price and activity failures
**Files:**
- `backend/app/providers/binance_provider.py:89, 99` — `except Exception: return None` / `return {}`
- `backend/app/jobs/signal_log.py:588–589` — `except Exception: pass`

All three catch blocks suppress exceptions with no log output. When prices fail to load or activity records fail to write, there is no trace of what went wrong (network error, rate limit, schema mismatch, etc.).

**Impact:** Silent failures that are impossible to debug. If Binance is rate-limiting or the activity log table has a schema issue, the system degrades silently with no signal to the operator.

## P2 — Medium: Signal Quality Degradation

### 6. Regime detection uses the current open (incomplete) weekly candle
**File:** `backend/app/jobs/signal_log.py:177`

```python
last = btc_weekly.iloc[-1]
```

If the signal scan job runs mid-week (Monday through Friday), `iloc[-1]` is the current open candle — not a completed weekly close. The EMA comparison uses an intraweek price as if it were a confirmed weekly structure.

**Fix direction:** Use `btc_weekly.iloc[-2]` — the last completed weekly close.

**Impact:** Regime classification can flip during the week as price moves intraweek, causing signals to be accepted or skipped based on incomplete data.

### 7. Conviction formula inconsistency between backtest and live signal logging
**Files:**
- `backend/app/trading/backtest_engine.py:454–458` (backtest)
- `backend/app/jobs/signal_log.py:216–219` (live signal scan)

**Backtest conviction formula:**
```python
oracle_pts = (abs(e_score) / 5) * 40    # Oracle score: 0–40 pts
titan_pts  = (t_confidence / 100) * 40  # Titan: 0–40 pts
bonus      = 10 if t_signal in ("BUY", "SELL") else 0
bonus     += 10 if abs(e_score) >= 4 else 0
conviction = int(min(100, oracle_pts + titan_pts + bonus))
```

**Live signal conviction formula:**
```python
base_pts      = (t_confidence / 100) * 60  # Titan: 0–60 pts
regime_bonus  = 20 if regime_aligned else 0
signal_bonus  = 10 if t_signal in ("BUY", "SELL") else 0
conviction    = int(min(100, base_pts + regime_bonus + signal_bonus))
```

Oracle is excluded from live conviction. Titan gets 40 pts max in backtest but 60 pts in live. A Titan signal with `t_confidence=80` and no Oracle scores 32 pts in backtest vs 48 pts live — different enough to cross gating thresholds differently.

**Impact:** Signals can clear the conviction threshold in live scanning but not in backtest (or vice versa), making backtested performance an unreliable predictor of live signal behavior. Oracle is deprecated from the UI but still affects backtest scoring.

### 8. EquityCurve component crashes with a single data point
**File:** `frontend/src/components/trading/EquityCurve.tsx:47`

```typescript
return PAD + ((i) / (values.length - 1)) * (W - PAD * 2);
```

When `values.length === 1`, this divides by zero, producing `NaN` for all SVG x-coordinates. The chart renders blank or broken.

**Fix direction:** Add an early guard: if `values.length < 2`, render a placeholder or no chart.

---

### 9. MSS pivot detection loop misses the most recent candles
**File:** `backend/app/indicators/calculator.py:394`

```python
for i in range(lookback, len(df) - lookback):
```

The loop stops `lookback` (default 2) candles before the end of the DataFrame. A pivot high or low in the most recent 2 candles can never be detected, because the inner loop accesses `df['high'].iloc[i+j]` which would be out of bounds.

**Impact:** Recent market structure shifts are always invisible until at least 2 candles after they occur. This is a fundamental design constraint — documenting it helps avoid confusion when MSS appears "lagged."
